# Combobox baseline (2026-11-25)

npm frappe-ui 1.2.0 (`wc/node_modules/frappe-ui`) vs the clone at HEAD 451ae0a (`frappe-ui/`). Both use reka-ui 2.11.0 and Vue 3.5.46. The two Combobox sources differ only in two RTL class names (`text-start`, `ms-1`), and every measurement here matches between them within noise.

## Files
- `raw/tables.md`: all timing, count, memory and dev-split tables (generated by `bench/report.cjs`).
- `raw/{npm,clone}-profile-attribution.md`: CPU-profile attribution of mounting 100 Comboboxes (5 profiles each, 50 us sampling, prof build mapped through source maps).
- `instance-tree.txt`: the 20 instances of one closed Combobox, with the reactivity objects each creates and its dev-mode self time.
- `raw/*-dev-rerenders.json`: which components re-render on mount, on prop updates and on open/close, and what triggered each render (dev `renderTriggered`).
- `raw/*.json`, `raw/*.cpuprofile`: the raw data.
- `cypress-run.log`, `cypress-formcontrol.log`: frappe-ui's own Combobox tests run here.

## Harness (`wc/combobox-speed/bench/`)
```
. ~/fb/env.sh; export NODE_PATH=~/fb/pw/node_modules; cd wc/combobox-speed/bench
FUI=npm|clone|/abs/frappe-ui-checkout  MODE=prod|prof|count|dev  npx --no-install vite build   # -> dist/<tag>-<mode>
node run.cjs <tag>-<mode> timing|memory|counts|profile|dev|rerenders [runs] [outDir]
node analyze-profile.cjs <tag>-prof <outDir>/<tag>-prof-mount100-run*.cpuprofile
node report.cjs <outDir> npm clone [patched]
./run-all.sh ../baseline/raw 7          # all of the above for FUI_LIST="npm clone" (about 12 min)
FUI_LIST=/abs/path TAG=patched ./run-all.sh ../after/raw 7   # a patched checkout; then report.cjs with npm clone patched
```
- The bench uses Vite 6 and Vue 3.5 from `wc/node_modules`, with Tailwind 3 and frappe-ui 1.2.0's preset. Bare imports from a checkout that has no node_modules resolve from `wc/node_modules` (the `clone-deps` plugin). It imports `src/components/Combobox/Combobox.vue` directly.
- Each control is rendered as `BenchCell > Combobox` (one cell per control, as the es-* runtime does per host), with Desk variant-B props: `options [] | 20`, `modelValue null`, `query ''`, `open false`, `filterable false`, `openOnFocus/openOnClick false`, `placeholder`, `emptyText`, `portalTo undefined`, `class`, v-model handlers for open/query/modelValue, and an `item-html` slot.
- Modes:
  - prod: minified, Vue in production mode.
  - prof: prod, unminified, with source maps.
  - count: prod, with @vue/reactivity's ReactiveEffect, ComputedRefImpl, RefImpl, ObjectRefImpl, CustomRefImpl, EffectScope, Dep, watch() and reactive Proxy constructors instrumented at build time by a transform. Each creation is logged with the active effect scope, so it can be attributed to its component instance. Nothing in `node_modules` is modified.
  - dev: Vue DEV build with `app.config.performance` and a `renderTriggered` spy.
- Timing: every scenario starts in a fresh page and browser context. Cold is the first mount in that page; warm is the 4th mount in the same page. Three numbers are recorded:
  - `js`: from the state change through Vue's nextTick flush.
  - `painted`: until 2 rAFs later, so it is quantized to frames.
  - `task`: the CDP TaskDuration delta.
- CDP `ScriptDuration` does not count `Runtime.evaluate` work (it reads 0), so `js` is the scripting number.
- Headless Chromium 1200 (Playwright 1.56). One browser at a time. 7 runs; cells are median [min–max].

## Where mount time goes (prof build, 100 mounts, ~317 ms sampled)
- **Vue machinery is 66% of self time:** runtime-core 39%, reactivity 18%, shared 6%, runtime-dom 4%. GC adds 9% and (program) 7%.
- **frappe-ui code is about 5% inclusive:** Combobox.vue setup, computeds and render plus useInputLabeling, useReactiveSlots, usePortalTarget and useFilteredGroups. useFilteredGroups costs 0.6 ms per 100 mounts. Each of the others costs under 1 ms per 100.
- **reka code is about 7% self, plus the Vue work it causes.** The largest single library hotspot is `useForwardExpose` (3.4% self, 4.8% inclusive). It runs in about 10 of the 20 instances, and each run creates a ref, a computed and an onUpdated hook, and calls defineProperty once for every prop.
- **The cost is per instance, not per feature.** 20 instances per closed control:
  - 5 are `Primitive` and 1 is `PrimitiveSlot`. In the dev split, Primitive alone is 25% of self mount time.
  - The closed popover subtree is still mounted (ComboboxPortal, Teleport, ComboboxContent, Presence: 4 instances, about 10% of the dev split).
  - The rest is ListboxRoot, ListboxFilter, PopperRoot, PopperAnchor and ComboboxTrigger.
- **Every mount pays a second render.** After mounting, 7 instances per control render again: Teleport (`useMounted`), ComboboxPortal, ComboboxAnchor, PopperAnchor, PrimitiveSlot, ComboboxTrigger and 4x Primitive. The post-mount flush is 23–36% of mount js (40 ms of 175 warm; 161 ms of 445 for 300).
- **Any prop change on a closed control re-renders the whole tree.** Changing query, placeholder or options re-renders 15–17 of the 20 instances, Presence and ComboboxContent included. That works out to 0.5–0.7 ms per control.

## frappe-ui's tests
- **Cypress component tests:**
  - `src/components/Combobox/Combobox.cy.ts`: 82 tests.
  - `src/components/shared/slotReactivity.cy.ts`: 14 tests.
  - `src/components/FormControl/FormControl.cy.ts`: 31 tests; it mounts Combobox through FormControl.
  - The package script is `cypress run --component --browser chrome`.
- **Vitest:** `useFilteredGroups.test.ts` and `selection/utils.test.ts` have 11 tests; `yarn test` runs vitest across the whole repo.
- **They run here.** I used a local git clone of the frappe-ui clone, so the original is untouched: `wc/combobox-speed/test-clone`. Its install, about 2 min, used caches in `wc/combobox-speed/.cache`, which holds about 1.8 GB including Cypress 15.9.0.
  ```
  cd wc/combobox-speed/test-clone; . ~/fb/env.sh
  npx vitest --run src/components/shared/selection src/components/Combobox        # 11/11 pass
  CYPRESS_CACHE_FOLDER=$PWD/../.cache/Cypress npx cypress run --component \
    --browser ~/.cache/ms-playwright/chromium-1200/chrome-linux64/chrome \
    --spec src/components/Combobox/Combobox.cy.ts,src/components/shared/slotReactivity.cy.ts   # 96/96 pass, ~44 s
  ... --spec src/components/FormControl/FormControl.cy.ts                                # 31/31 pass
  ```
  The first FormControl run failed with "Failed to fetch dynamically imported module": Vite re-optimized its dependencies on first use. The second run passed. To test the `combobox-perf` branch, copy the changed files, or apply the patch, into `test-clone` and rerun.
