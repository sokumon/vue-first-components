# Variant A: Vue components (the v8 pattern) for Link and Select

The class stays the API. A `.vue` file draws it with frappe-ui's components, unchanged, in v8's single `createApp` tree. Everything was measured on the bench, on top of legacy + one-vue, and diffed against `../results/*-legacy*`.

## What is on the bench while A is applied

| file (bench) | source here | what |
|---|---|---|
| `frappe/public/js/tw_a.bundle.js` | `src/tw_a.bundle.js` | Replaces `vue_first8.bundle.js` (mode v8's entry) and loads before `controls.bundle.js`. It defines v8's Control, ControlInput and ControlData (the user's files, unchanged), then ControlLink, ControlSelect and their views, and mounts the one app. |
| `tw_a/ControlLink.vue` | generated by `tools/gen_link_vue.py` | 35 of link.js's methods, verbatim. Only `make_input` and `setup_awesomeplete` are replaced (`tools/link_overrides.js`). `fetch_map` is a computed getter. |
| `tw_a/LinkInput.vue` | | `frappe.ui.form.LinkInput`, mounted with `new` into `input_area`. It draws `.link-field > .awesomplete > Combobox`, with `.link-btn/.btn-clear/.btn-open` in the Combobox's suffix slot, and hands back `$input` (the Combobox's own `<input>`) and the buttons. |
| `tw_a/awesomplete_shim.js` | | `control.awesomplete`: Awesomplete's state machine and events (open, select, selectcomplete, close) over the Combobox. `list`, `isOpened`, `ul`, `close()`, `evaluate()` and `get_item()` work, so link.js's own handlers run as they are. |
| `tw_a/ControlSelect.vue`, `tw_a/SelectInput.vue` | | A select.js port. The native `<select>` stays `$input`, kept out of sight with a 1 px clip, and frappe-ui's Select draws it and writes picks back with `.val()` plus a native `change`. |
| `tw_a/select_globals.js`, `frappe/form/controls/link_globals.js` | | The globals of select.js and link.js, verbatim. The Awesomplete `get_item` patch stays in `controls.bundle.js` because autocomplete, multiselect and multiselect_pills need it. |
| `tw_a/fui-a.js`, `tw_a/fui-a.css.js` | `fui/` (vite and tailwind, `node fui/css.cjs`) | frappe-ui 1.2.0 `Combobox` and `Select` from npm (`wc/node_modules`, the same copy and toolchain as wc/jq). `vue` is external, which means one-vue. The CSS is scoped to `:where(.tw-fui)`, and only the `:root` variables that Desk lacks are kept. |
| tracked: `hooks.py`, `control.js`, `web_form.bundle.js` | `bench-A.patch` | Mode v8's include order, with `tw_a.bundle.js` in place of `vue_first8.bundle.js`. `control.js` drops base_control, base_input, data, select and link (link becomes `link_globals`). `web_form.bundle.js` imports `tw_a.bundle.js` first. |

**Scripts:**
- `session.sh <cmd>` holds `bench.lock` for the whole run. It takes variant B's hooks entries off if B is on the bench, runs `apply.sh`, then `<cmd>`, then `revert.sh`, and puts B back as it was.
- `run-all.sh <label>` runs the harness, perf, the specs twice, and the full suite.

## Results (label `A`)

The raw files are in `results/` and `../results/{harness,perf}-A.json`.

- **Harness:** 82 steps, 0 step errors, 0 console errors. Against legacy:
  - **0 behaviour differences.**
  - 20 api differences, all `api.chain`: v8's `Component` base class adds one level.
  - 7 structure differences: `.select-icon` is missing.
  - 3 event-order differences and 1 request difference, all timing (see `results/diff-A.md`).
- **Link and Select specs, run twice:** 46 passed, 6 failed (legacy: 48 passed, 4 failed).
  - The 4 Gender failures are environmental, and the same as legacy.
  - The 2 extra failures are `control_select` "toggles placeholder". It checks legacy markup (`.select-icon`, `.placeholder`) that frappe-ui's Select replaces.
- **Full suite:** 133 passed, 16 failed, 7 did not run (legacy: 135 passed, 14 failed). The 2 new failures:
  - `control_select` placeholder, for the reason above.
  - `grid.spec` "parks the Link dropdown on the grid". It tests grid_row.js:1000, which moves `.awesomplete > ul` onto the grid because a cell clips it. Here the list is frappe-ui's fixed-position popover, so only the hidden stand-in `<ul>` gets parked. Desk core and the spec would have to change in lockstep.
- **Perf:** see the table in the structured result. Opening forms costs 0–15% more. Creating controls costs 7× legacy for Link and 16× for Select. JS heap is 124 KB per Link and 224 KB per Select, against 6 KB and 0 KB.
- **Size:** `tw_a.bundle.js` is 80.7 KB gz, of which frappe-ui is 54.2 KB gz JS and 10.5 KB gz CSS.
