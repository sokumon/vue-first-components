Vue-first frappe.ui

Each frappe.ui.* class comes out of a .vue file. The class holds state and the public API, its template draws it, and each instance renders as its own small Vue root, sharing one app context. Existing callers, prototype patches and jQuery writes keep working.

Status: design study, nothing in the repo Spike 5: 57 of 57 checks in jsdom Real desk: 122 of 122 checks in Chromium, with real frappe-ui Issue #1: all 10 flaws fixed

The picture

Three separate things: the class instance others call, the Vue component that renders it, and the DOM, which can sit anywhere on the page.

What you write

A normal .vue file. There is no hand-written class and no h().

<script>
export default {
	name: "frappe.ui.Counter",        // the global it becomes
	methods: {                        // the public API: on the prototype, patchable
		bump() { this.add(1); },
		add(by) { this.count = this.count + by; },
	},
};
</script>

<script setup>                      // optional: composition for everything else
const count = ref(0);
const doubled = computed(() => count.value * 2);
</script>

<template>
	<span @click="bump()">{{ count }} | {{ doubled }}</span>
</template>

The rule: anything callers or patches can reach goes in methods. Everything else can be composition. Pure <script setup> can't be the public API, because nothing is on the prototype at load and internal calls skip patches.

Using both blocks is my recommendation. You haven't confirmed it yet.

From file to class

Build time

  1. compileScript leaves the script as it is and records its bindings.
  2. compileTemplate emits render.
  3. The plugin sets script.render = render.
  4. New: one added line calls frappe.ui.define(script).

When the bundle loads

  1. define builds a real class.
  2. methods go on the prototype.
  3. computed become fields a caller can still assign.
  4. extends becomes a real prototype chain, so super works.

What new frappe.ui.Sidebar() does

new frappe.ui.Sidebar()
  shallowReactive(this)                 this.x = y now re-renders
  render(view, mount_point)             one synchronous call, its own small root
    view setup: <script setup>, created(), renders()   hooks and refs belong to the view
    first render; top-level nodes go into host          host read now, after created()
    onMounted hooks, template refs
  any error above: tear down, rethrow   Vue would only log it
  mounted()
return self                             $wrapper and fields are ready here

Nothing global holds the controller. Its view re-renders from a queue of its own, which Vue runs ahead of every component in the tick, so a page with thousands of controllers costs the same per controller as one with ten.

The desk renderer is createRenderer over Vue's own exported nodeOps and patchProp, about 90 lines. With define.js, vue_internals.js (every Vue internal in one file, checked at startup) and desk_router.js, that's roughly 870 lines of our own code, comments included.

What happens to each method when it's ported

  • Builds markup: becomes the template (make_dom, sidebar.html).
  • Reads or pokes the DOM: stays as it is (expand_parent_section, setup_click_away).
  • Returns data: the template calls it, so patches apply (menu_items).
  • Factories: frappe.ui.button and the rest stay as one-line aliases over a full class. Not built yet.

Proven and not proven

Ran and passed

  • Sidebar's public API, with opendesk's add_item, move and patch flow (jsdom).
  • Prototype patches, class extends, super, expandos (jsdom and Chromium).
  • A real desk in Chromium: real frappe-ui Button and Dropdown inside an emitted class, focus, keys, portals, transitions, desk routing.
  • Controller lifetime under forced GC, in Chromium.
  • Forms: Control, ControlInput and ControlData ported, with every other control still extending them. Frappe's own 156 Playwright specs for controls, forms, grids and dialogs give the same 135 passes as the original controls, and form load times are unchanged.
  • Four adversarial review rounds: 58 more defects, each reproduced, fixed and covered by a check.

Not run, and could change the design

  • Bootstrap's modal JS on a Vue-drawn $wrapper.
  • Grid and Dialog themselves: they run on v5 controls, but their own markup is still jQuery.
  • Web forms: they load the controls without the desk's v5 runtime.
  • The build step: esbuild-plugin-vue3 can't compile frappe-ui (it is prebuilt with Vite here), and doesn't emit frappe.ui.define or __imports yet.

Build time

The v5 bundle doesn't change desk build time: node esbuild --production --apps frappe takes 5.2–5.4 s with or without it (median of 5), and it builds alone in ~0.18 s. bench build --app frappe takes ~32 s warm and ~43–47 s with island caches cleared; the studio and flow Vite builds are most of that. The bundle is 375 KB minified: Vue 218 KB (each desk Vue bundle carries its own copy today), frappe-ui's Button and Dropdown 135 KB, the v5 runtime 15 KB.
